---
title: "Get Direct Message"
description: "Retrieve the delivery status, timestamp, and WhatsApp message ID of a direct message"
---

The `GET /api/v1/messages/:id` endpoint retrieves the record and delivery status of a previously dispatched direct message using its operation ID.

Queries are strictly isolated to the workspace associated with your API key. Attempting to access a message belonging to another workspace returns a `404 not_found` error.

### Authentication & Permissions

- **Method**: `GET`
- **Path**: `/api/v1/messages/:id`
- **Required Scope**: `messages:read`
- **Headers**:
  - `Authorization: Bearer YOUR_API_KEY` (required)
  - `X-Request-ID: <string>` (optional client trace ID)

---

## Path Parameters

<ParamField path="id" type="string" required>
  The unique message operation ID returned by `POST /api/v1/messages/send` (e.g. `msg_01hy8z9q2w4e1234`).
</ParamField>

---

## Request Examples

<CodeGroup>

```bash cURL
curl -X GET "https://wareply.indexai.co.zw/api/v1/messages/msg_01hy8z9q2w4e1234" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Accept: application/json"
```

```javascript Node.js
const messageId = "msg_01hy8z9q2w4e1234";

const response = await fetch(`https://wareply.indexai.co.zw/api/v1/messages/${messageId}`, {
  method: "GET",
  headers: {
    "Authorization": "Bearer YOUR_API_KEY",
    "Accept": "application/json"
  }
});

const data = await response.json();
console.log(data);
```

```python Python
import requests

message_id = "msg_01hy8z9q2w4e1234"

response = requests.get(
    f"https://wareply.indexai.co.zw/api/v1/messages/{message_id}",
    headers={
        "Authorization": "Bearer YOUR_API_KEY",
        "Accept": "application/json"
    }
)

print(response.json())
```

</CodeGroup>

## Response Attributes

<ResponseField name="data" type="object" required>
  The message status record.

  <Expandable title="data properties">
    <ResponseField name="id" type="string" required>
      Stable operation identifier matching the requested `:id`.
    </ResponseField>
    <ResponseField name="account_id" type="string" required>
      UUID of the WhatsApp account that dispatched the message.
    </ResponseField>
    <ResponseField name="to" type="string" required>
      The destination phone number in normalized E.164 format.
    </ResponseField>
    <ResponseField name="type" type="string" required>
      Message payload type (`text` or `media`).
    </ResponseField>
    <ResponseField name="status" type="string" required>
      Current operational status: `sent`, `accepted`, `queued`, `processing`, `failed`, or `dispatch_uncertain`.
    </ResponseField>
    <ResponseField name="external_message_id" type="string | null" required>
      Confirmed WhatsApp message ID returned by WhatsApp servers upon successful transmission.
    </ResponseField>
    <ResponseField name="created_at" type="string" required>
      ISO 8601 timestamp when the send request was received.
    </ResponseField>
    <ResponseField name="sent_at" type="string | null" required>
      ISO 8601 timestamp when WhatsApp confirmed network delivery.
    </ResponseField>
  </Expandable>
</ResponseField>

## Common Errors

| Status | Code | Description |
| :--- | :--- | :--- |
| `400` | `invalid_request` | The `:id` parameter was not provided. |
| `401` | `unauthorized` | Missing, expired, or invalid API key. |
| `403` | `insufficient_scope` | API key lacks the `messages:read` scope. |
| `404` | `not_found` | Message does not exist or belongs to another workspace. |
| `429` | `rate_limited` | Exceeded 60 requests per minute. |
