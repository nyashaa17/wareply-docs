---
title: "Send Direct Message"
description: "Dispatch a 1-to-1 WhatsApp text or media message to an international phone number"
---

The `POST /api/v1/messages/send` endpoint sends a direct, 1-to-1 WhatsApp message to a validated recipient phone number. Messages are dispatched through the specified WhatsApp account instance, honoring built-in delivery pacing to maintain account standing.

### Authentication & Permissions

- **Method**: `POST`
- **Path**: `/api/v1/messages/send`
- **Required Scope**: `messages:send`
- **Headers**:
  - `Authorization: Bearer YOUR_API_KEY` (required)
  - `Content-Type: application/json` (required)
  - `Idempotency-Key: <string>` (optional, strongly recommended for safe retries)
  - `X-Request-ID: <string>` (optional client trace ID)

---

## Request Parameters

<ParamField body="account_id" type="string" required>
  The UUID of the WhatsApp account in your workspace to send from (e.g. `acc_01hy8z9q2w4e`).
</ParamField>

<ParamField body="to" type="string" required>
  The recipient's phone number formatted in international E.164 notation (e.g. `+263782092900`).
  
  - Must include country code and start with `+` or digits without spaces or symbols.
  - Must be between 7 and 15 digits.
  - Local numbers starting with `0` and raw JIDs containing `@` are rejected.
</ParamField>

<ParamField body="type" type="string" default="text">
  The message payload type: `text`, `media`, `image`, `video`, or `document`. If omitted, defaults to `text`.
</ParamField>

<ParamField body="text" type="string">
  The message text body.
  
  - Maximum 4,096 characters.
  - Required if `asset_id` is not provided.
  - `message` is accepted as an alias.
</ParamField>

<ParamField body="asset_id" type="string">
  Media asset identifier uploaded through the Wareply Dashboard.
  
  - Required if `text` is omitted.
  - Must refer to an existing asset belonging to this account and workspace.
  - `assetId` is accepted as an alias.
</ParamField>

<ParamField body="caption" type="string">
  Optional text caption accompanying a media attachment. Maximum 1,024 characters.
</ParamField>

## Request Examples

<CodeGroup>

```bash Text Message
curl -X POST "https://wareply.co.zw/api/v1/messages/send" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ord-10023-alert" \
  -d '{
    "account_id": "acc_01hy8z9q2w4e1234",
    "to": "+263782092900",
    "text": "Hello, your order #10023 has been packed and is ready for collection."
  }'
```

```bash Media Attachment
curl -X POST "https://wareply.co.zw/api/v1/messages/send" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: inv-5542-send" \
  -d '{
    "account_id": "acc_01hy8z9q2w4e1234",
    "to": "+263782092900",
    "type": "document",
    "asset_id": "ast_01h8a9b2c3d4e5f6",
    "caption": "Your monthly receipt for September 2026."
  }'
```

```javascript Node.js
const response = await fetch("https://wareply.co.zw/api/v1/messages/send", {
  method: "POST",
  headers: {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json",
    "Idempotency-Key": "unique-operation-key-123"
  },
  body: JSON.stringify({
    account_id: "acc_01hy8z9q2w4e1234",
    to: "+263782092900",
    text: "Hello from Wareply!"

```

```python Python
import requests

payload = {
    "account_id": "acc_01hy8z9q2w4e1234",
    "to": "+263782092900",
    "text": "Hello from Wareply!"
}

response = requests.post(
    "https://wareply.co.zw/api/v1/messages/send",
    headers={
        "Authorization": "Bearer YOUR_API_KEY",
        "Content-Type": "application/json",
        "Idempotency-Key": "unique-operation-key-123"
    },
    json=payload
)

print(response.json())
```

## Response Attributes

<ResponseField name="data" type="object" required>
  The message operation record.

  <Expandable title="data properties">
    <ResponseField name="id" type="string" required>
      Stable Wareply operation identifier (e.g. `msg_01hy8z9q2w4e1234`).
    </ResponseField>
    <ResponseField name="account_id" type="string" required>
      The sending WhatsApp account UUID.
    </ResponseField>
    <ResponseField name="to" type="string" required>
      The normalized destination phone number in E.164 format.
    </ResponseField>
    <ResponseField name="type" type="string" required>
      Payload type (`text` or `media`).
    </ResponseField>
    <ResponseField name="status" type="string" required>
      Terminal send state: `sent`. Indicates transmission to and acceptance by the WhatsApp network.
    </ResponseField>
    <ResponseField name="external_message_id" type="string | null" required>
      Confirmed WhatsApp network message identifier returned by WhatsApp's servers.
    </ResponseField>
    <ResponseField name="created_at" type="string" required>
      ISO 8601 timestamp when the message operation was recorded.
    </ResponseField>
    <ResponseField name="sent_at" type="string | null" required>
      ISO 8601 timestamp when the message was acknowledged by the WhatsApp network.
    </ResponseField>
  </Expandable>
</ResponseField>

```json
{
  "data": {
    "id": "msg_01hy8z9q2w4e1234",
    "account_id": "acc_01hy8z9q2w4e",
    "accountId": "acc_01hy8z9q2w4e",
    "to": "+263782092900",
    "type": "text",
    "status": "sent",
    "external_message_id": "3EB0ABCDEF1234567890",
    "externalMessageId": "3EB0ABCDEF1234567890",
    "created_at": "2026-09-13T03:50:00.000Z",
    "createdAt": "2026-09-13T03:50:00.000Z",
    "sent_at": "2026-09-13T03:50:01.250Z",
    "sentAt": "2026-09-13T03:50:01.250Z"
  }
}
```

<Note>
**Receipt Philosophy**: `sent` is the terminal API-visible state. It confirms the WhatsApp servers received the message and returned an external ID. Wareply does not expose handset-level double ticks (delivered) or blue ticks (read) through the Developer API.
</Note>

## Error Handling

| Status | Code | Cause & Resolution |
| :--- | :--- | :--- |
| `400` | `invalid_recipient` | Malformed phone number, non-digit characters, length outside 7-15 digits, or local prefix `0`. |
| `400` | `invalid_request` | Missing text and asset, text over 4096 chars, or illegal anti-abuse parameters (`parallel`, `delay <= 0`). |
| `401` | `unauthorized` | Missing or invalid API key. |
| `403` | `insufficient_scope` | API key lacks `messages:send`. |
| `403` | `account_access_denied` | API key whitelist forbids access to this `account_id`. |
| `403` | `plan_upgrade_required` | Current plan does not include Developer API access. |
| `403` | `quota_exceeded` | Monthly broadcast message quota exhausted. |
| `404` | `not_found` | Account not found in this workspace. |
| `404` | `account_unavailable` | Account is disconnected or initializing. |
| `409` | `idempotency_conflict` | A request with the same `Idempotency-Key` is currently executing. |
| `422` | `idempotency_key_mismatch` | Same `Idempotency-Key` was sent with a different payload. |
| `429` | `rate_limited` | Exceeded 60 requests per minute. |
| `502` | `message_failed` | Definitive WhatsApp delivery failure. Operational quota is refunded automatically. |
| `504` | `dispatch_uncertain` | Ambiguous timeout. Status recorded as `dispatch_uncertain`. Do not retry without checking status. |
