---
title: "Get Group Details"
description: "Retrieve metadata for a specific WhatsApp group from the local snapshot"
---

The `GET /api/v1/groups/:id` endpoint returns detailed metadata for a single WhatsApp group from the cached snapshot.

### Authentication & Permissions

- **Method**: `GET`
- **Path**: `/api/v1/groups/:id`
- **Required Scope**: `groups:read`
- **Headers**:
  - `Authorization: Bearer YOUR_API_KEY` (required)
  - `X-Request-ID: <string>` (optional client trace ID)

---

## Path Parameters

<ParamField path="id" type="string" required>
  The full WhatsApp group JID (e.g. `120363041234567890@g.us`).
</ParamField>

## Query Parameters

<ParamField query="account_id" type="string" required>
  The UUID of the WhatsApp account associated with the group (e.g. `acc_01hy8z9q2w4e1234`).
</ParamField>

---

## Request Examples

<CodeGroup>

```bash cURL
curl -X GET "https://wareply.co.zw/api/v1/groups/120363041234567890@g.us?account_id=acc_01hy8z9q2w4e1234" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Accept: application/json"
```

```javascript Node.js
const groupId = "120363041234567890@g.us";
const accountId = "acc_01hy8z9q2w4e1234";

const response = await fetch(`https://wareply.co.zw/api/v1/groups/${groupId}?account_id=${accountId}`, {
  headers: {
    "Authorization": "Bearer YOUR_API_KEY",
    "Accept": "application/json"
  }
});

const data = await response.json();
console.log(data);
```

```python Python
import requests

group_id = "120363041234567890@g.us"
account_id = "acc_01hy8z9q2w4e1234"

response = requests.get(
    f"https://wareply.co.zw/api/v1/groups/{group_id}",
    headers={
        "Authorization": "Bearer YOUR_API_KEY",
        "Accept": "application/json"
    },
    params={"account_id": account_id}
)

print(response.json())
```

</CodeGroup>

## Response Attributes

<ResponseField name="data" type="object" required>
  The group metadata record.

  <Expandable title="data properties">
    <ResponseField name="id" type="string" required>
      The WhatsApp group JID (e.g. `120363041234567890@g.us`).
    </ResponseField>
    <ResponseField name="name" type="string" required>
      Group subject or title.
    </ResponseField>
    <ResponseField name="participant_count" type="integer" required>
      Current number of members in the group.
    </ResponseField>
  </Expandable>
</ResponseField>

<Note>
**Backwards Compatibility**: The server also returns deprecated `participantCount` alongside canonical `participant_count`.
</Note>

---

## Response Example (HTTP 200)

```json
{
  "data": {
    "id": "120363041234567890@g.us",
    "name": "Regional Logistics Hub",
    "participant_count": 42
  }
}
```

## Common Errors

| Status | Code | Description |
| :--- | :--- | :--- |
| `400` | `invalid_recipient` | Group JID does not end in `@g.us` or is malformed. |
| `400` | `invalid_request` | `account_id` query parameter is missing. |
| `401` | `unauthorized` | Missing or invalid API key. |
| `403` | `insufficient_scope` | API key lacks `groups:read`. |
| `404` | `not_found` | Group not found in the account's current snapshot. |
