This guide walks you through authenticating your API key, verifying your workspace, and sending your first WhatsApp message through the Wareply Developer API.

## Prerequisites

Before calling the API, ensure you have:

1. **A Wareply Account on an eligible plan**: Free includes 500 Dashboard messages per month. Developer API access requires Standard or higher. Workspaces on the Free tier cannot authenticate against Developer API endpoints and will receive a `403 plan_upgrade_required` error.
2. **A Connected WhatsApp Account**: At least one WhatsApp phone number connected and in the `ready` state within your Wareply workspace.
3. **An API Key**: Generated from your Wareply Dashboard.

---

## Step 1: Generate an API Key

API keys are created and managed directly in the Wareply Dashboard:

1. Log in to your [Wareply Dashboard](https://wareply.co.zw).
2. Navigate to **Settings** (`/settings`) from the main sidebar.
3. Scroll to the **Developer API Keys** section.
4. Click **Create Key**. Enter a descriptive name (for example, `Production Backend`) and select the required scopes (for example, `accounts:read`, `messages:send`, and `messages:read`).
5. Copy the generated secret key (`wrp_live_...`) immediately. 

<Warning>
The full plaintext key is displayed only once at creation or rotation. If misplaced, you must rotate the key to generate a new secret.
</Warning>

---

## Step 2: Locate Your WhatsApp Account ID

You can discover accessible WhatsApp accounts programmatically or through the Wareply Dashboard:

1. **Programmatic Discovery**: Call [`GET /api/v1/accounts`](/api-reference/accounts/list) (requires `accounts:read` scope) to inspect connected account IDs, display names, and phone numbers.
2. **Dashboard Lookup**: Navigate to **Accounts** (`/accounts`) in your Wareply Dashboard, select your account, and copy the unique account UUID from the card or URL bar (for example, `acc_01hy8z9q2w4e1234`).
3. Keep this identifier available as your `account_id`.

## Step 3: Verify Your API Key

Verify your authentication, tenant workspace, and granted scopes by calling the `GET /api/v1/me` endpoint.

<CodeGroup>

```bash cURL
curl -X GET "https://wareply.co.zw/api/v1/me" \
  -H "Authorization: Bearer wrp_live_<YOUR_API_KEY>" \
  -H "Accept: application/json"
```

```javascript Node.js
const apiKey = "wrp_live_<YOUR_API_KEY>";

const response = await fetch("https://wareply.co.zw/api/v1/me", {
  method: "GET",
  headers: {
    "Authorization": `Bearer ${apiKey}`,
    "Accept": "application/json"
  }
});

const data = await response.json();
console.log(data);
```

```python Python
import requests

api_key = "wrp_live_<YOUR_API_KEY>"

response = requests.get(
    "https://wareply.co.zw/api/v1/me",
    headers={
        "Authorization": f"Bearer {api_key}",
        "Accept": "application/json"
    }
)

print(response.json())
```

</CodeGroup>

If the response returns HTTP 200, your credentials, workspace association, and plan entitlements are valid.

## Step 4: Send Your First Message

Dispatch a text message using `POST /api/v1/messages/send`. Provide the recipient phone number in international E.164 format (with a leading `+` and country code).

<CodeGroup>

```bash cURL
curl -X POST "https://wareply.co.zw/api/v1/messages/send" \
  -H "Authorization: Bearer wrp_live_<YOUR_API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "account_id": "YOUR_ACCOUNT_ID",
    "to": "+263782092900",
    "text": "Hello from the Wareply Developer API!"
  }'
```

```javascript Node.js
const apiKey = "wrp_live_<YOUR_API_KEY>";

const response = await fetch("https://wareply.co.zw/api/v1/messages/send", {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${apiKey}`,
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    account_id: "YOUR_ACCOUNT_ID",
    to: "+263782092900",
    text: "Hello from the Wareply Developer API!"
  })
});

const result = await response.json();
console.log(result);
```

```python Python
import requests

api_key = "wrp_live_<YOUR_API_KEY>"

payload = {
    "account_id": "YOUR_ACCOUNT_ID",
    "to": "+263782092900",
    "text": "Hello from the Wareply Developer API!"
}

response = requests.post(
    "https://wareply.co.zw/api/v1/messages/send",
    headers={
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json"
    },
    json=payload
)

print(response.json())
```

</CodeGroup>

### Expected Response

```json
{
  "data": {
    "id": "msg_01hy8z9q2w4e1234",
    "account_id": "acc_01hy8z9q2w4e1234",
    "to": "+263782092900",
    "type": "text",
    "status": "sent",
    "external_message_id": "3EB0ABCDEF1234567890",
    "created_at": "2026-09-13T03:50:00.000Z",
    "sent_at": "2026-09-13T03:50:01.250Z"
  }
}
```

<Note>
**Naming Convention**: `snake_case` properties (`account_id`, `external_message_id`, `created_at`, `sent_at`) are canonical. The API also returns deprecated camelCase aliases (`accountId`, `externalMessageId`, `createdAt`, `sentAt`) for backwards compatibility.
</Note>

## Step 5: Retrieve Message Status

Retrieve the persistent record and metadata of any direct message using its operation ID (`msg_...`).

<CodeGroup>

```bash cURL
curl -X GET "https://wareply.co.zw/api/v1/messages/msg_01hy8z9q2w4e1234" \
  -H "Authorization: Bearer wrp_live_<YOUR_API_KEY>" \
  -H "Accept: application/json"
```

```javascript Node.js
const messageId = "msg_01hy8z9q2w4e1234";

const response = await fetch(`https://wareply.co.zw/api/v1/messages/${messageId}`, {
  headers: {
    "Authorization": "Bearer wrp_live_<YOUR_API_KEY>",
    "Accept": "application/json"
  }
});

const result = await response.json();
console.log(result);
```

```python Python
import requests

message_id = "msg_01hy8z9q2w4e1234"

response = requests.get(
    f"https://wareply.co.zw/api/v1/messages/{message_id}",
    headers={
        "Authorization": "Bearer wrp_live_<YOUR_API_KEY>",
        "Accept": "application/json"
    }
)

print(response.json())
```

</CodeGroup>

## Understanding the "sent" Status

When the API returns `"status": "sent"`, it confirms that:

1. The message passed all validation, tenancy, scope, and quota checks.
2. The message was dispatched to the WhatsApp worker process.
3. The WhatsApp socket transmitted the payload to WhatsApp's servers.
4. The WhatsApp network acknowledged the transmission and returned a confirmed WhatsApp message ID (`external_message_id`).

<Note>
**Important note on receipts**: `sent` is the terminal status visible via the Developer API. Wareply does not track or expose handset-level delivery receipts (double checkmarks) or read receipts (blue checkmarks) on the Developer API surface.
</Note>
